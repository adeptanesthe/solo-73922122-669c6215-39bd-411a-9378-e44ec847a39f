# 双人录音复听分段

给编辑使用的双人录音复听网页：上传一段不超过 30 秒的 16 kHz 单声道 WAV，
为甲、乙两位说话人各标出 3～8 段互不重叠的参考语音，后端对整条录音做
短时声学分析，把每个判为语音的帧分给甲 / 乙 / 待复核（停顿与纯底噪为静音），
合并相邻同标签帧后在时间轴上展示分段与置信度，点击任意片段即可跳转到原录音对应位置复听。
即使其中一方说得很轻、音量接近底噪，只要参考里有清楚的发言，也能正常分段。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

然后浏览器打开 <http://localhost:8000> 。

页面上的「载入演示音频」按钮会生成一段合成的双人录音并自动填好参考段，
可直接点击「开始分析」体验完整流程。

## 本地开发（不用 Docker）

```bash
pip install -r backend/requirements.txt
pip install -r backend/requirements-dev.txt   # 自测需要
uvicorn app.main:app --app-dir backend --reload
# 打开 http://localhost:8000
```

自测直接运行 `python -m pytest` 即可（`pytest.ini` 已把 `backend` 加入导入路径）。

## 使用流程

1. **载入录音**：选择本地 WAV（≤30 秒、16 kHz、单声道），或点「载入演示音频」。
2. **标注参考**：在波形上按住拖动选择片段，点「设为甲参考 / 设为乙参考」；
   每人 3～8 段，所有参考段互不重叠；每段可单独试听、删除。
3. **开始分析**：时间轴上显示 甲（蓝）/ 乙（橙）/ 待复核（黄）/ 静音（灰）
   分段，颜色不透明度反映置信度；点击片段或明细表行跳转复听。

参考段越界、相互重叠、数量不足（<3 或 >8）、段长 <0.3 秒、
参考内有效语音不足、录音几乎全静音等情况，服务端会拒绝分析并返回中文原因。
参考语音不足时会区分两种原因：参考段里只有静音/底噪，或参考里的说话声太轻、
与底噪难以区分，并提示改选更清楚的片段。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/demo` | 返回演示 WAV（base64）与配套参考标注 |
| POST | `/api/analyze` | multipart：`file`=WAV，`references`=JSON `{"A":[[s,e],...],"B":[[s,e],...]}`（秒） |

`/api/analyze` 响应：

```json
{
  "duration": 12.0,
  "frame_count": 1198,
  "frame_hop_ms": 10.0,
  "vad_threshold": 0.858,
  "segments": [
    {"label": "silence", "start": 0.0, "end": 0.448, "confidence": 1.0, "frames": 44},
    {"label": "A", "start": 0.497, "end": 1.107, "confidence": 0.9232, "frames": 61}
  ],
  "stats": {"A": 441, "B": 423, "review": 96, "silence": 238}
}
```

`label` ∈ `A`（甲）/ `B`（乙）/ `review`（待复核）/ `silence`（静音）。

## 算法说明（NumPy + SciPy）

1. **分帧**：25 ms 窗、10 ms 帧移（16 kHz 下 400/160 采样点）。
2. **特征**（`backend/app/features.py`）：预加重 → 汉明窗 → 功率谱 →
   26 通道 Mel 滤波器组，得到每帧逐频带能量。**刻意不使用整体能量**
   作为主要判据：轻声与底噪响度接近时，整体能量无法区分两者。
3. **底噪与语音检测**（`classify.estimate_noise`）：
   - 取全片最安静的约 20% 帧，逐频带取中位数作为底噪谱，并迭代几次，
     避免把弱语音算进底噪；
   - 每帧取信噪比最高的 6 个频带，计算超出底噪的平均对数幅度，
     记作“语音证据”（衡量是否出现了新的谱结构，而不是整体变响）；
   - 用证据最低的噪声帧分布定出**双阈值**：低阈值抓轻声，高阈值确认强语音；
     低阈值片段只有成段（≥80 ms）或邻近强语音时才保留。
     这样参考以外的轻声不会漏掉，停顿 / 纯底噪也不会被连成语音。
4. **说话人特征**（`features.cepstral_features`）：逐频带谱减底噪 →
   DCT 丢弃第 0 阶（整体增益）→ 每帧倒谱均值归一（消除谱倾斜）→
   3 帧平滑；响度不同但谱形相同的声音会得到接近的特征。
5. **归属判断**（`classify.classify_frames`）：汇总每位说话人全部参考段内的
   有效语音帧，标准化后各拟合一个对角协方差高斯模型（协方差向全局方差收缩）；
   每个语音帧比较两个模型的对数似然决定归属。
6. **置信度与待复核**：
   - 区分度：两人似然差按参考帧尺度归一；
   - 典型度：获胜模型似然相对参考典型水平的位置。对语音证据较弱的帧，
     按“证据相对参考的比例”放宽门槛，使同一人参考以外的轻声仍归给本人；
     证据中等但确实不像两人的帧（第三人、双人混音）仍判为待复核。
   - 置信度 < 0.65 的帧标为 `review`。
7. **静音**：未被语音检测命中的帧一律标为 `silence`（停顿、纯底噪）。
8. **合并**（`classify.merge_segments`）：相邻且标签相同的帧合并为段，
   段置信度取帧均值。

## 自测

```bash
python -m pytest backend/tests -v
```

覆盖：正常双人录音的分段正确性、全静音输入的拒绝、静音尾巴的标注、
第三说话人 / 双人混音等低置信输入产生待复核帧、参考越界 / 重叠 /
数量不足 / 非 16 kHz / 非单声道 / 超 30 秒 / 非 WAV 等非法输入的拒绝，
以及两种“底噪 + 轻声”场景（见下）。

### 轻声场景自测（`backend/tests/scenarios.py`）

| 场景 | 构造 | 断言 |
| --- | --- | --- |
| 参考本身是轻声 | 乙的参考与参考以外发言都在音节内约 8 dB SNR，甲较响 | 分析完成；乙的音节帧 ≥80% 归为乙，≤5% 标静音，≤5% 误判给甲 |
| 参考较响、别处轻声 | 乙的参考约 25 dB SNR，参考以外的轻声约 9 dB SNR | 同上；参考以外的轻声不被标成静音 |
| 停顿 / 纯底噪 | 两人发言之间的间隙与开头结尾 | 各间隙 ≥90% 帧为静音 |
| 参考里只有底噪 | 乙的三段参考全落在停顿区 | 400「参考语音不足：所选片段里几乎只有静音或底噪…」 |
| 参考语音太轻 | 乙的参考只比底噪高约 0.5 dB（基本埋在底噪里） | 400「参考语音不足：参考段里的说话声太轻…」 |
| 纯底噪录音 | 全长只有噪声 | 400「有效语音过少…」 |

## 交付核对

### 已实现
- FastAPI 后端：上传校验（WAV、16 kHz、单声道、≤30 s）、参考标注校验
  （3～8 段、不越界、不重叠、段长下限、参考内有效语音下限），全部以 400 + 中文原因拒绝；
  参考语音不足时区分“只有静音/底噪”与“语音太轻、与底噪难分”两种原因。
- 逐频带底噪估计 + 谱证据双阈值滞回语音检测（轻声不漏、底噪不误检）。
- 去增益的倒谱说话人特征、双高斯模型帧级归属、
  按证据强度自适应放宽的典型度判定、待复核标记、相邻同标签帧合并。
- 原生前端（无框架）：波形显示与拖动选区、参考段管理（试听 / 删除）、
  分段时间轴（标签 + 置信度）、点击片段跳转复听、分段明细表。
- 演示音频生成（合成双人语音 + 预填参考段），一键体验完整流程。
- Docker Compose 单服务交付（后端托管前端静态文件，含健康检查）。

### 已验证（本地自测，Python 3.11）
- `python -m pytest backend/tests`：18 项全部通过，覆盖
  - 正常输入：合成双人录音分段边界铺满时间轴、相邻段标签互不相同，
    各说话时段内正确标签占语音帧 ≥85%、误判为对方 ≤5%、回合间隙判为静音；
  - 静音输入：全静音 / 纯底噪录音返回 400「有效语音过少」；语音后的长静音尾正确标为静音段；
  - 低置信输入：第三说话人区域与双人混音区域均产生待复核帧；
  - 轻声场景：上述两种轻声构造下，发音帧 ≥80–94% 正确归属，≤5% 静音、≤5% 误判；
    停顿与底噪区 ≥90% 为静音；
  - 参考不足：参考落在纯底噪 / 语音过轻时返回 400 并给出对应中文原因；
  - 非法输入：参考重叠 / 数量不足或过多 / 越界、非 16 kHz、非单声道、
    超 30 秒、非 WAV、参考 JSON 无法解析，均返回 400 及中文原因。
- 端到端冒烟：`uvicorn` 实际启动后，`GET /`、`GET /app.js`、`GET /api/health`、
  `GET /api/demo` 均 200；按前端相同方式 multipart 上传演示 WAV 至
  `/api/analyze` 返回 200，分段统计 甲 441 / 乙 423 / 待复核 96 / 静音 238 帧。
- 前端 `app.js` 通过 `node --check` 语法检查；`docker-compose.yml` 通过 YAML 解析检查。

### 未完成 / 限制
- 仅支持两人场景；模型为单高斯（每说话人一个对角协方差），
  对真实录音中多人音色相近、强噪声、重叠说话的区分能力有限，
  这类帧依赖“待复核”兜底，需人工确认。
- 语音检测依赖“底噪大致平稳、说话时出现新的谱结构”；
  若底噪是与人声频谱相近的持续音乐 / 键盘声，轻声仍可能被并入静音，
  需人工复听确认。
- 未做帧标签的时序平滑（严格按需求只做相邻同标签合并），
  真实录音上可能出现短促的孤立段。
- 分析结果不持久化，刷新页面需重新上传分析。
- 交付环境无 Docker 守护进程，镜像构建与 `docker compose up` 未在本机实际执行；
  Dockerfile 与 compose 配置按标准实践编写并经静态检查。
